# OpenList NVENC transcode worker

This public image packages the official OpenList `cmd/worker` binary with Debian FFmpeg, an optional NVENC argument wrapper, and a small local configuration page. The upstream Worker source is checked out and compiled by GitHub Actions at build time; it is not forked or patched in this repository.

The wrapper is deliberately outside the upstream process. It receives the same FFmpeg arguments generated by OpenList and adds selected NVENC output options only when the job already requests `h264_nvenc` or `hevc_nvenc`. H.264/HEVC selection, bitrate, scale, audio, and HLS settings remain controlled by the OpenList Master Job Profile.

## Run

The container expects NVIDIA Container Toolkit on the host when `hwaccel=nvenc` is selected. A typical deployment publishes the configuration page on port 8080 and persists `/var/lib/openlist-worker`:

```sh
docker run -d --name openlist-nvenc-worker \
  --gpus all \
  -p 8080:8080 \
  -v openlist-worker-state:/var/lib/openlist-worker \
  -e OPENLIST_MASTER=http://openlist:5244 \
  -e OPENLIST_SECRET='set-the-same-secret-in-openlist' \
  -e OPENLIST_UI_PASSWORD='choose-a-local-ui-password' \
  ghcr.io/8u6cherhu/openlist-transcode-worker:latest
```

Set `OPENLIST_UI_PASSWORD` when the page is reachable beyond a trusted local network. The secret is stored only in the persisted container config and is masked in the page. Do not put a real Master URL, secret, token, password, private key, or local media path in this repository.

The repository also includes `compose.worker.example.yml`; copy it to a deployment directory and provide the variables in a local `.env` file.

Set `OPENLIST_NETWORK` in the local `.env` file to the Docker network shared by the Master and Worker. Keep real deployment values out of the public repository:

```dotenv
OPENLIST_WORKER_SECRET=<same secret configured in OpenList>
NVIDIA_WORKER_GPU=0
OPENLIST_UI_PASSWORD=<optional local UI password>
OPENLIST_WORKER_NAME=nvenc-worker
OPENLIST_WORKER_CAPACITY=1
```

The worker's configuration volume is separate from its temporary transcoding directory, so UI settings persist across image updates.

Open `http://server:8080/` to edit Worker connection settings and the NVENC options. Saving writes the config atomically and restarts only the official Worker child process. If the page is unavailable, the same settings can be supplied with `OPENLIST_MASTER`, `OPENLIST_SECRET`, `OPENLIST_WORKER_NAME`, `OPENLIST_CAPACITY`, `OPENLIST_HWACCEL`, and `OPENLIST_WORKDIR`.

## NVENC options

The initial defaults are `preset=p5`, `tune=hq`, `rc=vbr`, `multipass=qres`, spatial AQ and temporal AQ enabled, AQ strength 8, three B-frames, and lookahead disabled. These are output options, so they are applied only to NVENC jobs. `cq=0` means the wrapper does not add a CQ override; the bitrate from the Master remains in force. Lookahead, B-frames, B-ref mode, and multipass support depends on the GPU generation and the FFmpeg/NVIDIA driver in the running container. If a selected option is unsupported, FFmpeg will report it in the Worker log and the job will fail visibly rather than silently changing the requested profile.

The UI can tune NVENC behavior, but it cannot change a Master Job Profile that never requests an NVENC encoder. Configure the OpenList Master with `transcode_run_mode=remote`, `transcode_worker_secret`, `transcode_hwaccel=nvenc`, and an output codec of `h264` or `hevc` before testing.

## Upstream update model

The workflow has an `openlist_ref` dispatch input. It checks out that upstream tag or commit, builds `./cmd/worker`, and copies the resulting binary into the image. The page, config schema, entrypoint, and FFmpeg wrapper live in this repository and do not modify upstream files. Updating OpenList therefore means selecting a newer upstream ref and rebuilding the image; no merge of local changes into `cmd/worker` is required.

The workflow also scans the public build context for common private data patterns before publishing. GitHub Actions uses its ephemeral `GITHUB_TOKEN` only for package publishing; no token is stored in the repository.

## Local smoke test

```sh
python3 -m py_compile entrypoint.py scripts/ffmpeg-nvenc-wrapper.py
python3 -m http.server 8080 --directory web
```

The GitHub runner has no NVIDIA GPU. Verify NVENC itself on the target host with `ffmpeg -hide_banner -encoders | grep -E 'h264_nvenc|hevc_nvenc'` and `ffmpeg -hide_banner -hwaccels | grep cuda`.
